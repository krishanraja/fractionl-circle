## Executive Summary

Core product is functionally coherent and security-conscious in the obvious places (RLS broadly enforced, no secrets in `src/`, Stripe webhook properly verified, OAuth state is single-use + TTL'd). It is **not** production-clean. Three findings warrant immediate attention: (1) `generate-user-insights` runs with service role but accepts an unvalidated `user_id` in the request body with optional auth - cross-tenant data read is possible; (2) `send-sms` ships `Access-Control-Allow-Origin: *` on a Twilio-spending mutation endpoint; (3) **zero of 12 LLM call sites set a request timeout, and `generate-sunday-letter` persists raw model output as `sunday_letters.text_body` without validation** - this combines cost runaway, prompt-injection persistence, and hallucinated-PII-as-truth in one pipeline. Underneath that: TypeScript `strict: false` is hiding 31 errors (5 surface even under the relaxed config), 18 `npm audit` vulns (9 high), `react-hook-form` and `@tanstack/react-query` are installed but bypassed everywhere in favour of raw `useState` + direct Supabase calls, `.env.example` is stale (4 vars vs 19 referenced), and `DOCS.md` was last edited 18 days ago and no longer matches the surface it describes.

**Win:** Supabase data isolation is solid. All 35 edge functions except `generate-user-insights` are correctly gated (`requireAuth`, `CRON_SECRET`, Stripe signature, or OAuth-state). No service-role key in the client bundle. The skill note claiming `.env` is committed is **outdated** - `.env` is in `.gitignore` and git-history scan returned zero secret hits beyond the intentionally-public anon JWT.

**Production Ready:** **CONDITIONAL** - ship-blockers listed in §Verdict.

## Findings by Severity

### CRITICAL (ship-blockers)

**C1 - `generate-user-insights` uses service role with optional auth; `body.user_id` unvalidated**
`supabase/functions/generate-user-insights/index.ts:32` instantiates a service-role Supabase client. Auth extraction at `:38–47` is conditional; `:51` reads `targetUserId = body.user_id || authedUser.id`. Because auth is optional and the body overrides, any caller with the public function URL can pass arbitrary `user_id` and trigger LLM-powered insight generation over another tenant's `user_profiles` / `user_behavior_logs` / `feature_usage` / `monthly_goals` / `daily_progress` (reads at `:63–100`). Cost amplification and cross-tenant data read.
**Fix:** Require auth JWT unconditionally OR require `CRON_SECRET` header when auth is absent. Validate `body.user_id === authedUser.id` unless the `CRON_SECRET` path is taken.

**C2 - `generate-sunday-letter` persists unvalidated LLM output to DB**
`supabase/functions/_shared/sundayLetterCore.ts:192` takes `narrative = String(result.choices[0].message.content ?? '').trim()` and writes it directly to `sunday_letters.text_body` at `:199`. No schema validation, no content sanitisation, no length cap on output. Prompt contains user names + match rationale (`:163–175`), so model-hallucinated PII or injection payloads from upstream data become durable content served back to the user.
**Fix:** Validate with Zod, enforce max length, strip markdown injection vectors, reject on empty/placeholder output. Tag records with the model version that generated them.

**C3 - Zero LLM call sites set a request timeout (12 sites)**
None of the 12 LLM fetch calls pass an `AbortSignal` with a timeout. A hung upstream (OpenAI / Anthropic / Lovable / Gemini) will exhaust the edge-function execution budget and user request with no circuit-breaker. Affected sites:

**C4 - `send-sms` uses wildcard CORS on a data-mutating Twilio endpoint**
`supabase/functions/send-sms/index.ts:5` - `'Access-Control-Allow-Origin': '*'`. The auth JWT check at `:37–55` blunts exploitation, but the preflight itself allows any origin to attempt credentialed request flows and any browser extension or cross-site call to enumerate error messages. Every other function uses the origin-allowlist in `_shared/compliance.ts:10–15`.
**Fix:** Switch to `getCorsHeaders(req)` from `_shared/compliance.ts`.

### HIGH

**H1 - TypeScript is uncovering real bugs that current config swallows**
`tsconfig.app.json:18` sets `strict: false`. Even so, `tsc --noEmit` currently emits **5 errors** in `src/lib/circleIngest.ts` (lines 309, 327, 362, 481, 504) - `PersonCandidate` type predicate misalignment and `null`-to-non-null assignments. Under `--strict`, the error count is **31**. The app is shipping despite this because nothing gates the build on `tsc`.
**Fix:** Fix the 5 current errors first (real runtime risk - null slipping into a structure typed non-null). Then add `tsc --noEmit` to the `build` npm script. Ramp `strict` incrementally via `strictNullChecks: true` + `noImplicitAny: true` in isolation, then flip `strict: true`.

**H2 - 18 `npm audit` vulnerabilities (9 high, 7 moderate, 2 low)**
Examples: rollup GHSA-mw96-cpmx-2vgc (high, path traversal), yaml 2.0.0–2.8.2 stack-overflow (moderate). `npm audit fix` is offered; review patch diffs first. `lovable-tagger@1.1.7` is a likely stale dev-only plugin tied to the old Lovable platform - verify necessity.

**H3 - `react-hook-form` + `@tanstack/react-query` are installed but unused**
`package.json` declares both (`react-hook-form@7.53.0`, `@tanstack/react-query@5.56.2`). Grep shows zero `useForm(` or `useQuery(` / `useMutation(` imports in app code. Every form (`AuthPage.tsx:413–616`, `FirstVoice.tsx:38–343`, `ConciergeBookingSheet.tsx:26–189`, `MatchCard.tsx`, `ProfileSettingsSheet.tsx`) hand-rolls state with `useState` + direct `supabase.functions.invoke(...)` calls. No Zod schemas on any form. No query invalidation - stale UI after mutations is enforced by manual refetch or component remount. Large, systemic consistency / reliability problem.
**Fix:** Either rip the deps out and own the choice, or migrate forms to `react-hook-form` + Zod + reuse `src/components/ui/form.tsx` (already scaffolded but orphan - verify call sites). Route all `supabase.functions.invoke` through TanStack Query mutations with `onSuccess` invalidation.

**H4 - Rate limits are per-instance in-memory maps**
`supabase/functions/_shared/compliance.ts:171` stores limiter state as `Map<string, { count, resetAt }>`. Supabase Edge functions scale horizontally - instance A's counter is invisible to instance B. A user hitting 20 req/min on a single instance may hit 60+ req/min across three. Affected: `extract-ideas`, `parse-voice-*`, `parse-screenshot`, `transcribe`, `parse-contact-image`, `parse-onboarding`, `dedupe-circle`, `generate-sunday-letter`.
**Fix:** Move to a `rate_limits` table (PK `(user_id, bucket)`, increment via upsert + `ON CONFLICT` in one round-trip) or a Redis provider from the Marketplace.

**H5 - Dual lockfile drift**
`bun.lockb` (2026-03-15) and `package-lock.json` (2026-04-12) coexist. Whichever CI ignores will diverge silently from the other. Migration from Bun → npm was not completed.
**Fix:** Delete `bun.lockb`. Add a CI check that fails if both exist.

**H6 - OAuth lacks PKCE**
`oauth-google-start/index.ts:36` and `oauth-microsoft-start/index.ts:32` generate state with double `crypto.randomUUID()` and rely on TTL + single-use deletion at callback. State alone is sufficient for confidential web clients (current posture), but PKCE is the new baseline and would be required if you ever add a native/extension client or host the OAuth in a place where the authorization code can be intercepted.
**Fix:** Add `code_challenge` (S256) on start, persist `code_verifier` alongside state, send on token exchange.

**H7 - `parse-screenshot` leaks upstream error text to edge logs**
`supabase/functions/parse-screenshot/index.ts:132–133` throws `new Error(\`Anthropic error: ${res.status} ${text.slice(0, 300)}\`)`. That string lands in the edge-function log stream. On certain failure modes Anthropic echoes back prompt fragments in the error body - which for this function can include the user's uploaded screenshot metadata or OCR'd text.
**Fix:** Log status + request ID only; never the response body substring.

**M4 - N+1 query in `resolve-contact`**
`supabase/functions/resolve-contact/index.ts:280–285` loops over `weak` and awaits a `.from('talent_contact_identities').select(...)` per item. Bounded by list size but trivially fixable.
**Fix:** Single `.in('<join-col>', weakIds)` query.

**M5 - ErrorBoundary doesn't catch async and has no telemetry sink**
`src/components/ErrorBoundary.tsx:16–65` is a class component wrapping the tree at `src/App.tsx:69`. `:27` logs via `console.error` and calls an optional `onError` prop (not wired). Two TODOs at `src/main.tsx:11,16` acknowledge Sentry is missing. Async errors (promise rejections, fetch failures, effect errors) fall through to the browser console.
**Fix:** Add `window.addEventListener('error', ...)` + `unhandledrejection` listener in `main.tsx` and ship Sentry (or a simpler Vercel Log Drain + custom sink). Close the TODOs.

**M6 - ~20 raw HTML form elements bypass shadcn primitives**
Examples: `AuthPage.tsx:175, 256, 298, 359, 399` use `<button>`; `ConciergeBookingSheet.tsx:85, 97` and `MatchCard.tsx:201` use raw `<textarea>`; `MatchCard.tsx:152, 175, 183, 207, 219, 235, 247` use raw `<button>` with icons and no `aria-label`. Visual drift is inevitable.
**Fix:** Migrate to `Button` / `Textarea` from `src/components/ui/`. Add `aria-label` to every icon-only button.

**M7 - `Skeleton` component exists but is never used**
`src/components/ui/skeleton.tsx` is imported zero times across screens. Loading is handled exclusively by `PageLoader` (`src/components/ui/loading-spinner.tsx`). TodayScreen / CircleScreen / StreamsScreen / AskScreen show a generic spinner instead of a shape-matching placeholder.
**Fix:** Add list-shaped skeletons to the four screens; keep `PageLoader` for route-level lazy loading only.

**M8 - 5 form inputs lack `<Label>` association**
`ConciergeBookingSheet.tsx:85, 97` (textarea), `MatchCard.tsx:201` (textarea), `CrmCsvDrop.tsx:84` (hidden file input), plus likely peers in `ProfileSettingsSheet.tsx`. Screen-reader users lose the labelled-field affordance.

**M9 - Icon-only buttons without `aria-label`**
At least `MatchCard.tsx:152, 175, 183, 207, 219` and several in `DedupeReviewSheet` / `CircleScreen`. `aria-label` appears in the repo only 7 times - low coverage relative to the interaction surface.

**M10 - `generate-user-insights` silent fallback**
`generate-user-insights/index.ts:442` falls back to a rule-based path when the LLM call fails. No log-level is raised; the user gets output indistinguishable from the LLM path. Over time you will not know what fraction of "AI insights" were rule-based.
**Fix:** Emit a log event with the path taken and persist a `generation_source` column.
